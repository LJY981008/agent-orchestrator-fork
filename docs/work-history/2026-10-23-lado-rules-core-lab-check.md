# 2026-10-23 LADO 규칙 코어 — 랩 확인과 capability 문구

> 브랜치 `feat/lado-rules-core` · S15 엔트리의 "다음에 볼 것"(실제 앱 확인) · 소유자 승인 2026-10-23("문구만 지금 고침")

## 의도/목적 — 왜 이 작업을 하나

S15 까지 단위 테스트로만 본 화면과 흐름을 실제 데몬과 렌더러로 확인한다. 찾은 결함 가운데 작은 것만 이 브랜치에서 고친다.

## 방법

- 격리 랩: `HOME`·`AO_DATA_DIR` 를 스크래치 폴더에 두고 `AO_LADO_DEV=on AO_LADO_DEV_PRESENCE=1`, 트래커 토큰은 가짜. dev-web 렌더러를 Playwright 로 열어 UI 언어 한국어, 라이트·다크로 봤다.
- 트래커와 오케스트레이터가 만들 행(태스크 5, 계획 요청 4, 계획 리비전 4, 계획·이슈 블롭)만 SQLite 에 직접 넣었다. 승인과 규칙 변경은 모두 실제 화면과 API 로 했다. 스텁은 쓰지 않았다.

## 결과

- 브라우저 승인 경로가 `policySha256` 을 함께 보낸다. 승인 트랜잭션에 `lado-policy/1` 스냅숏(스냅숏 규칙 6행)과 감사 이벤트 `plan.approved`(actor `human:dev-presence`)가 같이 남는다.
- 전역 규칙 하나를 끄면 dry-run 영향 대화상자에 승인된 #1 이 뜨고, 변경을 확인하면 #1 이 `review_required` 가 된다. 규칙 탭은 "승인 뒤 규칙이 바뀜 · 제거됨: …" 을 문제 목록 위에 보인다(S15 순서).
- cursor 태스크 #2 를 승인하면 `blocked` 가 되고 푸터의 계획 승인 버튼이 꺼진다(S15 F1). 보드는 계획 레인에 규칙 확인 필요·차단됨 카드를, 대기열에 승인됨 카드를 보인다.
- 설정 → 규칙, 프로젝트 설정 → 규칙, 규칙 편집기(충돌 규칙 포함), 영향 대화상자는 라이트·다크 모두 깨지지 않았다. 브라우저 콘솔과 데몬 로그에 LADO 오류가 없다.

## 고친 것

- capability 문제 세 가지(unsupported·unverified·degraded)가 어느 규칙 때문인지 말하지 않았다. 데몬은 문제마다 `rules` 를 보내지만 8개 로캘 문구 어디에도 `{{rules}}` 가 없었다. 예: "Cursor은(는) 이 규칙에 필요한 규칙 텍스트을(를) 적용할 수 없습니다." 그래서 무엇을 끄면 되는지 화면에서 알 수 없었다.
- 8개 로캘 문구에 규칙 이름을 넣었다. ko 는 보간 뒤에 조사가 오지 않는 문장으로 바꿨다: "Cursor에서는 규칙 텍스트 적용을 지원하지 않습니다. 이 기능이 필요한 규칙: …".
- `lib/lado-rules.test.ts`·`lib/lado-errors.test.ts` 가 규칙 이름을 단언한다. 전에는 규칙이 빠진 문구를 단언했다.
- 검사: 관련 5 파일 36 통과, 프런트 전체 `8555 passed | 7 skipped`, `typecheck` 통과.

## 남긴 것

- 태스크·프로젝트 규칙 목록은 만든 순서, 그다음 id 순이라 보호 규칙 둘 사이에 "한국어 커밋 메시지" 가 낀다. 설정 화면은 보호 규칙을 위로 모은다. 바꿀지는 다음에 정한다.
- 한국어가 단어 중간에서 줄바꿈된다("합니/다."). 앱 전체에 `keep-all` 이 없어서이고, 이 브랜치 범위 밖이다.
- 랩 데몬은 데스크톱 앱이 띄우지 않아 스냅숏의 `aoBuild` 가 비어 있다. 앱이 데몬을 띄울 때 버전을 넣으므로 정상이다.
